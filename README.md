# 바 주크박스 (Bar Jukebox)

바에서 손님이 QR로 곡을 신청하면, 바의 Mac에서 Apple Music으로 순서대로 틀어주는 시스템.

## 구성

- **손님 면** (`/`): QR을 찍으면 뜨는 모바일 페이지. 닉네임 한 번 입력 → 곡 검색 → 신청.
- **바텐더 면** (`/admin`): 재생중/대기열/최근재생 표시, 스킵·삭제·순서조정(드래그)·제한없는 곡 추가.
- **재생 루프**: `osascript`로 Music.app을 제어. 큐에서 다음 곡의 앨범을 `music://`로 열고, 재생 중인 앨범의 트랙 전환이 완료될 때마다 확인하면서 요청 곡까지 이동한다. 이동 중에는 Music.app 볼륨을 0으로 만들고 끝난 뒤 원래 볼륨을 복구한다.

## 쿨타임 규칙

닉네임 기준으로 **동시에 큐+재생중에 곡이 1개까지만** 들어갈 수 있다. 본인 곡이 재생되거나 삭제된 뒤에 다시 신청 가능. 바텐더가 추가하는 곡은 제한 없음.

## 실행

바의 Mac에서 (Apple Music 구독이 연결된 계정, Music.app 로그인 상태):

```bash
cd bar-jukebox
bun install
cp .env.example .env
# .env의 ADMIN_TOKEN을 긴 랜덤 문자열로 변경
bun run dev
```

- 손님용: `http://<바-MAC-IP>:5173/` — QR 코드 생성해서 테이블에 비치.
- 바텐더용: `http://<바-MAC-IP>:5173/admin` — `.env`의 `ADMIN_TOKEN`을 사용.
- API 흐름 확인: `BASE_URL=http://localhost:5173 bun test-flow.ts`

## 작동 확인

- **이 Mac에서 확인됨**: Music.app AppleScript `open location`, `stop`, `play`, `next track`, 현재 트랙 ID, 볼륨 제어.
- **정확한 곡 재생**: `Good News`(앨범 4번 트랙)와 `Get Lucky`(앨범 8번 트랙)를 HTTP 요청으로 실제 재생해 정확한 곡명/아티스트와 `playing` 상태를 확인했다.
- **실패 안전성**: 트랙 전환 실패 예외에서도 원래 볼륨을 복구하는 테스트를 통과했다.

## 주의점 / 트러블슈팅

- **Apple Music 구독**이 재생 Mac 계정에 있어야 함. 구독 없으면 미리듣기만 되거나 재생 안 됨.
- **라이브러리/카탈로그에 없는 곡**은 틀 수 없음. 애플 뮤직 미지원 곡은 신청 시 큐에 들어갔다가 전환 실패로 스킵됨(12초 내 `playing` 안 되면 다음 곡으로).
- iTunes 검색 결과의 `trackNumber`를 사용하므로 일반적인 단일 디스크 앨범을 기준으로 한다. 다중 디스크 앨범은 후속 보강 대상이다.
- **재생 종료 감지**는 1.5초 폴링. 일시정지(pause)는 "대기"로 간주해 큐를 넘기지 않음 — 바텐더가 마이크 쓸 때 일시정지해두면 됨. 다음 곡으로 넘기려면 스킵 버튼.
- **보안**: 손님 면은 열려있음(바 사설망 가정). 바텐더 면은 토큰 1개. 공용 와이파이면 리버스프록시+TLS+손님 면에도 간이 인증 추가 필요.
